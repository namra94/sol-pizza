# sol.pizza — the main site

The public site for Sol, an Italian-American restaurant in Tây Hồ, Hanoi, in the
"Printed menu" design: cream paper, centred type, red rules. Static HTML, no
framework, generated by `build/gen.py` and served by the Cloudflare Worker
`sol-pizza` (see `README-DEPLOY.md`). Every guest page is in English at `/…` and in
Vietnamese at `/vi/…`.

**Every page is public: sol.pizza is the whole site.** `HIDDEN` in `build/gen.py`
can take a page down (below). The `full-site` branch mirrors `main` at
**https://full-site-sol-pizza.polarized-jar.workers.dev**, with `noindex`, and with
every section still waiting for content shown and marked (see "Content still to
come" and `README-DEPLOY.md`).

### Taking a page down

`HIDDEN`, near the top of `build/gen.py`, lists the pages that aren't public by
their section: `'menu'` (Food, Wine and Bar go together), `'about'`, `'visit'`,
`'booking'`, `'events'`, `'private-dining'`. It is empty: every page is public. To take
one down, add its key, open a pull request, check its Preview URL, and merge. The
tab, the footer link, the home and 404 buttons, the sitemap entry, the structured
data, the share card and the redirects (to the home page in the same language, with a
302) all follow from the list, in both languages. To put it back, delete the key. While
anything is hidden, the header also has a Work with us tab.

## Build and deploy

```
npm ci                 # once: fonts, the minifiers and wrangler
npm run build          # the public site (every page not in HIDDEN), into ./dist
npm run build:full     # every page and every section waiting for content, noindex (what full-site shows)
npx wrangler dev       # check it locally (applies _redirects, unlike a plain static server)
npm run deploy         # builds the public site, then deploys it; see README-DEPLOY.md

npm --prefix check ci  # once, for the two below: Playwright, axe and Lighthouse, in check/
npm run og             # re-render the share cards (then npm run pack-assets)
npm run check          # both builds, behaviour, accessibility; add -- <URL> for Lighthouse there too
```

The two build modes are described in `build/README.md`. `check/` has its own
`package.json`: Workers Builds installs only the root one, so the site's build never
downloads a browser. On a machine of your own, run `npx --prefix check playwright install
chromium` once as well.

## Editing

Everything is generated from `build/gen.py`; edit there and rebuild. Anything
you hand-edit in `dist/` is overwritten by the next build.

### Words

Every line of copy appears twice, English then Vietnamese:

```python
t('Book a table', 'Đặt bàn')
```

Edit both, or the two languages drift apart. The build writes each page twice, the
English side at `/…` and the Vietnamese side at `/vi/…`. Vietnamese changes for review
are logged in `VI-CHANGES.md`.

### Opening day and the hours

Near the top of `build/gen.py`:

- `SITE_STATE`: `'preopening'` until the day we open, then `'open'`. It switches the home
  page's eyebrow, facts row and lead, the Booking and Visit lines, the descriptions and the
  opening hours in the structured data, and takes every "opening soon" line off the site.
- `OPENING_DATE`: the first day, `'YYYY-MM-DD'`, once it's set. The home page then says
  "Opening Thursday 5 November", and from that day's opening time the pages switch to open
  by themselves, in the browser. Set `SITE_STATE = 'open'` on the day too, so the
  descriptions and the structured data follow (LAUNCH-CHECKLIST.md, "Opening day").
- `HOURS`: the regular week (days, opening and closing time, last orders), written once
  and used everywhere hours appear, in both languages.

### Announcements

`build/announcements.json` holds the line that can run across the top of every page:
holiday and Tết hours, the next event. Each has an `id`, the moment it starts and ends
(`show_from`, `show_until`, Hanoi time with its `+07:00`), the line in English and
Vietnamese, and optionally a link. The pages show and hide it at those moments by
themselves, without a rebuild; a guest who closes it doesn't see it again. The file's
`note` has an example.

### Content still to come

A section that needs something we don't have yet (prices, photos, the team, the
booking terms…) is built, but kept off sol.pizza: `gate()` in `build/gen.py`. A whole
page that does (gift cards, an Eclipse edition without its details, the legal drafts
waiting for the lawyer) is in `WAITING`: built every time, written only in the full
build, and linked from nowhere public; delete its line to publish it. The full build
(full-site, and the `full/…` preview of each pull request) shows both with a yellow
**Content needed** label. Everything waiting is listed in `CONTENT-NEEDED.md`, with
where it goes and who has it; the build stops if a gated section isn't listed there.

Visit's questions (`VISIT_FAQ`: parking, access, paying, corkage, dress, dogs,
smoking, big groups) work the same way: write the answer as `t('English', 'Tiếng
Việt')` in place of `None`, and it goes live.

### Events

Eclipse, Sol's popup series, lives in `build/events-data.json`: one entry per edition,
with its nights, and once we have them its line, times, chefs, menu, price and how to
book (the file explains each field). `/events/` lists the editions coming up, then the
past ones; the home page shows the next one, after dark. An edition counts as coming up
until 23:59 on its last night, Hanoi time, and the browser moves it to Past then, so
nothing waits for a rebuild (an edition that runs past midnight, `18:00–01:00`, ends at
its closing time). Its own page, `/events/<slug>/`, goes live once its line (`summary_en`,
`summary_vi`) is in; until then it's listed with its dates. A new edition is just a new
entry: nothing else to change.

### The menu

Food, wine and bar live in `build/menu-data.json`. Each English field has a
`_vi` twin below it. Dish, wine and drink names stay as written in both
languages; only descriptions, section names and place names are translated.

Prices, once set, go in the data: `"price"` on each dish and drink, `"glass"` and
`"bottle"` on each wine, whole numbers in đồng (`185000`). They show as `185,000` on
English pages and `185.000` on Vietnamese ones, with "Prices in Vietnamese đồng (VND)"
once under the title; a page's "A first draft" note goes when every item on it has its
price. `"updated"` (`YYYY-MM-DD`) puts "Menu updated …" at the foot of each menu page.
The Food page explains its marks (Veg: vegetarian); add a mark only once the kitchen
confirms it, with its Vietnamese name (`tag_labels_vi`) and its meaning in both languages
(`tag_meaning`, `tag_meaning_vi`).
The menus print cleanly: no bars, banners or buttons on paper.

The wine and bar pages end with the line on alcohol (`drinks` in the data: "We don't
serve alcohol to anyone under 18…"). The count lines on the wine page ("3 wines, 2 by
the glass") and the Wine tab are generated from the data. The wine lead ("Thirty wines…") and the home and
wine meta descriptions ("26 wines by the glass") spell the counts out in words,
so the build stops if the list no longer has 30 wines, 26 by the glass, and
tells you what to update.

### Booking

Online booking waits for ResDiary. Once the widget is set up (ResDiary →
Promote → Widget configurator → Embed Code), paste its URL into
`RESDIARY_URL` near the top of `build/gen.py` and rebuild: the Booking page's
booking box then shows the widget and says "Book online below, or call or
email us." Until then the booking box gives the phone number, email and Instagram
as text to copy (the team's call, 23 Sep), and the phone bar has no Call button;
with `RESDIARY_URL` set they become a tap away (`CONTACT_LIVE`), with Zalo and WhatsApp
too once their numbers are in `ZALO` and `WHATSAPP`. If ResDiary gives the widget a
separate Vietnamese address, put it in `RESDIARY_URL_VI` (the Vietnamese page uses it). If
guests pay a deposit inside the widget, set `RESDIARY_PAYMENTS = True`: the pages then let
the widget's frame use the browser's payment feature (if its payment step comes from
another address, add that origin too: ask ResDiary). Under the widget there's always a way round it (call, Zalo,
email), and the booking terms ("Before you book") wait for their content
(CONTENT-NEEDED.md). Before online booking, `/booking/` has a form to ask for a table in
opening week.

### Enquiries and the newsletter

The enquiry forms write an email; nothing is stored on a server. Filling one in and
pressing **Send by email** opens the guest's email app with the message ready, to
`ENQUIRIES` (hello@sol.pizza), the subject in English so the inbox sorts them
(`Private dining — Lan`, `Opening week — Minh`) and the details in the page's language;
the message also appears on the page, to copy, for a computer with no email app. There
are two: groups and private dining (`/private-dining/#enquire`, where every "seven or
more?" line leads) and, before online booking, a table for opening week (`/booking/`).
The **Sign up by email** button in every footer sends "Please add this email address to
Sol's newsletter": the email from the guest's own address is their consent. Keep the
list somewhere the team can find it (LAUNCH-CHECKLIST.md, "Enquiries and the
newsletter"), and take people off it when they ask.

### Jobs

The opening team is six roles, each with a card on `/jobs/` (grouped Front of
house / Kitchen) and a page at `/jobs/<slug>/` in both languages:

- `build/jobs-data.json`: the round (posted, closing instant, start date,
  service charge estimate) and each role's slug, section, openings, base salary,
  card line and apply question, English and Vietnamese. The cards, the closing
  script, the share cards, the meta descriptions and the `JobPosting` take their
  dates and figures from here.
- `build/jobs/<slug>.md`: the job description word for word, the English block
  then the Vietnamese one (`# ` title, the eyebrow line, the facts table, the
  bold standfirst, then `##` / `###` headings, paragraphs and `- ` lists). Its
  text carries the same dates and figures, so edit it alongside the data. The
  build stops if they disagree: the facts table's base salary, openings, closing
  and start dates, and every salary band in the text (each must be the base, the
  service charge estimate or the total), because the ads quote the same numbers.

Apply buttons open an email to jobs@sol.pizza with the subject (`Pizzaiolo — `)
and a body in the page's language. After the closing instant a small script in the
page head shows "Applications for this round closed…" on the cards and pages, hides
every Apply button, and takes "We're hiring now" off `/jobs/` and "Build it with us"
off `/about/`; a build after the closing instant leaves them out altogether. To check
it, set `closes` to yesterday, build with `JOBS_ALLOW_DATE_DRIFT=1 npm run build` (the
descriptions still say 4 October), look, and set it back. The Vietnamese role pages
(`/vi/jobs/<slug>/`) have a Vietnamese share card: link job ads for Vietnamese
speakers there. Each page carries a `JobPosting` for search.

Filled roles are listed under "Recently filled" and link to their pages, which
are the original pages in `src/jobs/` re-wrapped in the site design with their
copy untouched: a "This role has been filled" note at the top, no apply button,
`noindex`. Those three are in English only: their Vietnamese pages
(`/vi/jobs/<slug>`) have the Vietnamese header, title and a line saying so, then the
English description.

### The kitchen: dough calculator and dough log

`/dough/` and `/dough/log/` are tools for the dough station, not pages for
guests. They sit behind one shared **kitchen password**: staff open
sol.pizza/dough/ on a phone, sign in once, and stay signed in on that phone for
30 days. The password is a Cloudflare secret, never in the repo; setting it and
changing it are in `README-DEPLOY.md`, "The kitchen". Changing it signs every
phone out.

- **The calculator** (`/dough/`): set the number of balls and their weight, and
  the weights for the mix follow. The formula is in baker's percentages with
  fresh yeast; the flour is a blend of pizza flour, whole wheat and rye (pizza
  flour is the rest); a preferment (poolish or biga) is made with pizza flour.
  The kitchen's temperature and air humidity are measured each time; the
  temperature also works out, under Water temperature, how warm the water should
  be and how much ice to use.
- **Logging a batch**: at the end of the calculator, the day, who mixed it, the
  dough's temperature after mixing and any notes. The batch, the flour, the
  kitchen and the weights go in with it.
- **The dough log** (`/dough/log/`): every batch, newest first under a heading
  per day, with a delete button, and a download of the whole log as a CSV for a
  spreadsheet. The log is kept in a Cloudflare D1 database, `sol-dough`.

The calculator opens on the house spec, `DOUGH_SPEC` near `build_dough()` in
`build/gen.py`: ball count and weight, waste, the formula, the flour blend, a
preferment, and the temperatures for the water. **Today's numbers are a starting
point, not Sol's spec**: set them with the Sous Chef, who owns the dough
programme, and rebuild. `PREFERMENTS` holds what poolish and biga start at when
picked. Anyone can change a number on the page for one batch; the address then
carries whatever of the batch differs from the house spec (`/dough/?n=60&h=68`),
so "Share this batch" sends it as a link (the share sheet on phones, a copied link
elsewhere), and "Back to the house spec" clears it.

The pages are written by `build/gen.py` like the rest; the arithmetic is in
`build/design/dough.js`, the log page's script in `build/design/dough-log.js`, and
the password and the log's API in `worker/index.js`, the Worker's own code, which
runs only for `/dough/*` and `/api/*`.

The kitchen's pages keep the shell every page had on 12 October 2026: both languages in
one page with the in-page EN / VI switch, the header with About · Menu · Booking, and the
old footer, styled by `build/design/kitchen/kitchen.css` and run by
`build/design/kitchen/kitchen.js` (frozen copies). Nothing the guest pages change reaches
them, and they have no cookie banner, phone bar, announcement bar or analytics, and no
`/vi/` copy (a `/vi/dough/` page would sit outside the Worker's password check; the build
stops if one is ever written). `npm run check` makes sure.

## How the languages work

Every guest page is two files: English at `/…` (`<html lang="en">`) and Vietnamese at
`/vi/…` (`<html lang="vi">`), each with its own title, description, canonical address,
share card and `hreflang` links to the other (English is the `x-default`), and both are
in the sitemap. `build/gen.py` assembles a page with every line in both languages, as
`t()` writes them, and keeps one side per file; links on a Vietnamese page go to
Vietnamese pages.

EN · VI in the header (and the menu sheet) are links to the same page in the other
language. The choice is remembered (`localStorage` key `sol-lang`): opening the home page
(`sol.pizza`) next time goes straight to `/vi/` for someone who chose Vietnamese. Nothing
else is redirected by it (a link to an English page opens in English), and the browser's
own language is never read: Google advises against that.

Old links still work: `?lang=vi` on any address (`sol.pizza/menu/?lang=vi`) opens the
Vietnamese page, keeping any other parameters, and `/privacy/#vi` opens
`/vi/privacy/`. A small script at the top of each English page does it; a Cloudflare
Redirect Rule can do the same at the edge (LAUNCH-CHECKLIST.md). A missing address under
`/vi/` shows the Vietnamese 404 page.

Vietnamese pages always use the free fonts (Philosopher, EB Garamond): the
brand fonts don't include the Vietnamese letters.

## Cookies and analytics

GA4 (`G-SLBWDVH550`) and the Meta Pixel (`856214124247013`) load only after the guest
says yes, on the guest pages only (never the kitchen's), from `build/design/site.js`:

- The cookie banner (at the foot of the window, on a first visit): **Accept all**,
  **Reject all** and **Settings** (Analytics, Advertising, both unticked), all alike.
  Before a choice, nothing loads from Google or Meta. Analytics loads Google Analytics in
  consent mode's basic form; Advertising loads the Meta Pixel and `src/pixel.js` (the
  careers events). The site works the same whatever the choice.
- The choice stays in the browser (`localStorage` key `sol-consent`) for 12 months, and
  is asked again sooner if the banner's wording changes (`CONSENT_VERSION` in
  `build/gen.py`). **Cookie settings** in every footer reopens it; taking a yes back
  removes that tool's cookies.
- `/privacy/cookies/` lists everything kept in the browser. If that changes, change the
  notice, the banner and `CONSENT_VERSION` together.
- Events, with a yes: `book_click`, `call_click`, `zalo_click`, `whatsapp_click`,
  `email_click`, `directions_click`, `menu_view` (with the section), `enquiry_submit`
  (once per form per visit, with the form: Private dining or Opening week) and
  `newsletter_signup`; with a yes to Advertising, the matching Meta events (`BookClick`,
  `Contact`, `FindLocation`, `ViewContent`, `Lead`). A finished booking
  (`booking_complete`, Meta's `Schedule`) is mapped but not sent: it happens inside
  ResDiary's widget, which the page can't see. Add `?debug_analytics=1`
  to any address to see each one in the browser's console (and in GA4's DebugView);
  `?debug_analytics=0` stops it.

## Fonts

Two typefaces and seven sizes, set in `build/design/tokens.css`: a display face
for headings and a serif for everything else, plus one hand-written phrase per
section. Small labels are the serif in capitals.

- **EB Garamond** (everything that isn't a heading, in both languages) is one
  of the free fonts below. It replaced Gryphius MVB on 24 Sep 2026, which read
  badly on screen and has no Vietnamese letters; nothing uses Gryphius now.
- **BN Arora** (headings, English pages) is self-hosted: it's licensed for web
  use, and the file travels in `build/assets.b64.json`. It has no Vietnamese
  letters, so Vietnamese headings use Philosopher. `build/README.md` has the
  details.
- **Plunct** (the one hand-written phrase per section, English pages; upright)
  comes from Sol's Adobe Fonts web project, kit `umo0non`, linked on every page
  without blocking the first paint. It can't be self-hosted, so never download
  or commit its fonts. Vietnamese pages set the phrase in EB Garamond italic.
  The kit also holds Gryphius MVB and Gryphius MVB Small Caps, which the site
  doesn't use; removing them from the web project makes the kit a little
  lighter. Keep the Creative Cloud plan behind the web project active. In Adobe
  Fonts, set the web project's font display to **swap** (it is "auto" today,
  which can hide the phrase for up to 3 seconds while Plunct loads).
- **Free fonts**, always loaded and Vietnamese-complete: Philosopher and EB
  Garamond, from the `@fontsource` npm packages. The build
  copies only the Latin, Latin Extended and Vietnamese files into
  `dist/assets/fonts/`.
